Preencha os blocos `describe` em `{spec_file}` para testar os métodos de `{service_file}`.
O arquivo `{service_file}` é SOMENTE LEITURA. Não altere o `beforeEach` do scaffold.

================================================================================
1. REGRAS NEGATIVAS MANDATÓRIAS (ANTI-PATTERNS PROIBIDOS)
================================================================================
- ❌ PROIBIDO: `service.metodo = jest.fn()` ou `jest.spyOn(service, ...)`. NUNCA mocke a própria classe/método sob teste. O método DEVE executar sua lógica real. Mocke apenas as dependências injetadas.
- ❌ PROIBIDO: Chamar `.mockResolvedValue()` sem argumento em TypeScript estrito. Use SEMPRE `.mockResolvedValue(null)` ou `.mockResolvedValue([])`.
- ❌ PROIBIDO: Deixar blocos `describe` vazios sem testes `it(...)`.
- ❌ PROIBIDO: Instanciar manualmente todos os campos de DTOs ou entidades complexas. Use SEMPRE `as any` em fixtures parciais (ex: `mockData as any`).

================================================================================
2. MATRIZ DE CENÁRIOS DE TESTE OBRIGATÓRIOS
================================================================================
Para cada método público da classe, implemente múltiplos testes cobrindo os seguintes cenários:

A. Caminho de Sucesso (Happy Path)
```typescript
it('should return result when inputs are valid', async () => {{
  // Arrange: configure retorno esperado dos colaboradores
  repository.find.mockResolvedValue([mockItem] as any);

  // Act: chame o método REAL do serviço
  const result = await service.metodo('param1');

  // Assert: verifique o retorno e a chamada à dependência
  expect(result).toBeDefined();
  expect(repository.find).toHaveBeenCalled();
}});
```

B. Branches Condicionais e Filtros (if/else, ternários e flags)
```typescript
it('should apply conditional logic when optional parameter is provided', async () => {{
  await service.metodo('value', true);
  expect(repository.createQueryBuilder().andWhere).toHaveBeenCalled();
}});

it('should bypass conditional logic when optional parameter is omitted', async () => {{
  await service.metodo('value', false);
  expect(repository.createQueryBuilder().andWhere).not.toHaveBeenCalled();
}});
```

C. Casos Limite (Empty State / Not Found)
```typescript
it('should return empty collection when no records exist', async () => {{
  repository.find.mockResolvedValue([]);
  const result = await service.metodo('param');
  expect(result).toEqual([]);
}});
```

D. Tratamento de Exceções (Sad Path)
```typescript
it('should throw exception when entity is not found', async () => {{
  repository.findOne.mockResolvedValue(null);
  await expect(service.metodo('invalid-id')).rejects.toThrow();
}});

it('should propagate errors when dependency rejects', async () => {{
  repository.find.mockRejectedValue(new Error('Database unavailable'));
  await expect(service.metodo('param')).rejects.toThrow('Database unavailable');
}});
```

================================================================================
3. GUIA ANTI-ERROS DE TYPESCRIPT (TYPEORM / BUILDERS / JEST)
================================================================================
Para evitar erros TS2345 / TS2339 / TS2352 de propriedades faltantes:

A. Callbacks e Builders (Brackets, WhereExpressionBuilder, QueryBuilder)
❌ ERRADO:
brackets.whereFactory({{ andWhere: jest.fn() }}); // Falha TS2345: faltam orWhere, where...

✅ CORRETO (Sempre use casting 'as any' no objeto ou variável):
brackets.whereFactory({{ andWhere: jest.fn() }} as any);
// OU
const mockQb: any = {{ andWhere: jest.fn() }};
brackets.whereFactory(mockQb as any);

B. Fixtures de Entidades e Retornos Parciais
❌ ERRADO:
repository.findOne.mockResolvedValue({{ id: '123' }}); // Falha por faltar propriedades da Entity

✅ CORRETO (Sempre use casting 'as any'):
repository.findOne.mockResolvedValue({{ id: '123' }} as any);

C. Chamadas sem retorno (Void / Undefined)
❌ ERRADO:
repository.save.mockResolvedValue();

✅ CORRETO:
repository.save.mockResolvedValue(null);
